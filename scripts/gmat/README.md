# GMAT planet expedition

The Solar Map expedition runs a local GMAT Console process for each requested forecast. It supports Mercury, Venus, Mars, Jupiter, Saturn, Uranus and Neptune; Earth is the departure point. The shared game state is authoritative on the server. A player must reach the station phase before starting a flight. Only the currently assigned Space Specialist can plan, forecast, execute, or end an expedition; other roles can monitor the shared flight and trajectory. If no Space Specialist is assigned, a flight crewmember at the station (including a solo player) can take that role from the expedition panel. Existing role swaps remain available when the role is already staffed.

## Setup

Set `GMAT_CONSOLE_PATH` to the absolute path of `GmatConsole.exe` (or the GMAT console executable on another platform). On this Windows machine the server also checks `E:\gmat-R2026a-local\bin\GmatConsole.exe` if the variable is absent. The executable must have a working GMAT installation and startup file. Restart the Node server after changing its environment.

`GET /api/gmat/status` reports whether the configured executable exists. Forecast failures and timeouts are reported to the crew; there is no silent approximation or fallback. The server allows one GMAT forecast at a time and limits a run to 15 seconds. Each run uses a temporary working directory in `server/.gmat-runtime`, removed afterward. Set `GMAT_TEMP_DIR` to override this location if GMAT cannot write there; GMAT must accept the directory's path syntax.

## How the simulation works

* `public/data/gmat-planet-seeds.json` holds educational initial states at 2000-01-01 UTC. `generate_planet_seeds.py` obtains planetary endpoints from GMAT DE405 and constructs two-body Lambert departure guesses from an idealized 6,778 km Earth orbit. The orbit is individually aligned for each destination and **is not historical or live ISS telemetry**. Outer-planet seed burns also have offline GMAT finite-difference refinements.
* Crew choose a burn delay and V/N/B delta-v components in metres per second. GMAT receives the current Sun-centred MJ2000Eq Cartesian state in kilometres and kilometres per second, the UTC epoch, the chosen Earth-relative VNB burn, and a fixed forecast window. For departure it integrates with an Earth-centred point-mass/SRP model until the craft reaches 1,000,000 km from Earth's centre, then switches to a Sun-centred model for the interplanetary leg. A departure that returns to 6,478 km from Earth's centre or remains nearby for five days stops early and is reported as not escaped; this simplified radius is not an atmospheric model. The suggested burn assumes zero delay, and delaying it changes the departure direction. Insertion uses the destination-centred model. Both outputs are Sun-centred and target-centred GMAT ephemerides. The game plots the spacecraft samples on the Solar Map with schematic logarithmic scaling; other atlas planets remain stylized.
* Fuel is tracked by the game using the ideal rocket equation with a fictional impulsive engine, 3,000 s specific impulse, 12,000 kg dry mass and 100,000 kg initial fuel. GMAT is configured with `DecrementMass = false`; the game applies the calculated fuel use after the committed burn. These vehicle values are educational assumptions and do not describe a real crewed spacecraft.
* The reported closest approach is the smallest **sampled** distance, generally at 6-hour or coarser intervals. The 1–100 planet-radii approach condition is a game rule; it is neither a precise closest approach nor proof of a safe encounter. Atmospheric, ring, radiation and collision hazards are not modeled in that gate.
* After an approach, players may forecast an insertion burn. The suggested burn is a two-body circularization guess, not a GMAT optimization. The bound-orbit and periapsis checks are two-body osculating estimates evaluated at the burn, not proof of a stable or operationally safe orbit; the follow-up numerical propagation covers only 0.02 days. Atmospheres and rings are not modeled.
* Execution replays the chosen GMAT samples at accelerated time. The game does not continuously invoke GMAT during playback, does not simulate departure from the real ISS, and does not move player avatars into a travelling spacecraft. Existing station avatars remain where they are.

`public/data/gmat-specialist.json` and `mars-transfer-export.script` are earlier historical GMAT Mars example data retained for reference; they are not the dynamic all-planet mission calculation.
